# Agent-Friendly 原则 — 直接复用你第 5 周那 4 条

## 原则 1 — search_knowledge：先查、再答
- 药老回答丹方 / 功法前，必须先调 `search_knowledge`
- 查不到就说不知道，不编；查到了要标来源
- 四要素：查什么、去哪查、查到什么、查不到怎么办，都要在代码里看得见

## 原则 2 — validateToolArgs：参数先对 schema
- 所有工具调用前先校验参数，不对就拒，不调模型重猜
- 报错三要素：哪个参数错了、应该是什么、怎么改
- 修正提示直接取自 schema 描述，不手写新文案

## 原则 3 — 去重 + 幂等是同一问题的两面
- 调用方去重：前端同一操作不重复发（按钮防抖、requestId）
- 服务端幂等：`trade` / `gamble` / `brew_pill` 带 `requestId`，同一 ID 只执行一次
- 生产上两者都要，缺一个都会重复扣费

## 原则 4 — 有副作用的操作放在 interrupt() 之后
- 交易、赌命、炼丹、渡口引魂：先弹窗确认，玩家点了确认才执行
- 取消后状态不变；确认后刷新也不重复执行（靠原则 3 兜底）
- 只读操作（查状态、查丹方、列商品）不用 interrupt

## 多智能体分工（10 月 28 日跑通的那套）
- Router 只分流一步、分完下场
- Supervisor 全场在线、只走需要的节点
- 主管不带员工工具；不同 worker 工具集互不重叠；结构化 done 状态 + 熔断器
