# Requirements — 幽冥修仙 MUD

> 赛道：Resurrection | 技术：Next.js + TypeScript + LangGraph.js + step_5_preview
> 范围锁死：3 地点 / 3 NPC / 1 主线 + 2 支线 / 境界 3 档

## R1 — 能玩一局完整的文字 MUD
玩家创建角色后，能在终端式界面里输入指令、看剧情推进、查看状态，完成主线即通关。

- WHEN 玩家打开首页 THEN 30 秒内能看到开场剧情 + 创建角色入口，不用登录
- WHEN 玩家完成主线「渡口引魂」THEN 看到通关结算（境界、修为、用时、关键抉择回顾）
- WHEN 玩家刷新页面 THEN 存档（境界 / 物品 / 任务进度）能恢复，不用重开

## R2 — 3 个地点，互相能走通
地点只有：宗门大殿、鬼市、幽冥渡口。每个地点有固定描述 + 可做的事，移动消耗精力。

- WHEN 玩家在任一地点输入 `去 鬼市` / 点地点按钮 THEN 切换到对应地点，精力 -1
- WHEN 精力为 0 THEN 不能移动，提示打坐恢复（每 10 分钟 +1，沿用同修录规则）
- WHEN 玩家在地点里输入无效指令 THEN 提示该地点能做的事，不崩、不卡死

## R3 — 3 个 NPC，工具集互不重叠
- 掌门清虚（宗门大殿）：发主线、推进剧情、结算任务
- 药老（宗门大殿偏殿 / 鬼市摊位？定在宗门大殿）：RAG 查丹方 / 功法、炼丹
- 鬼市商人夜枭（鬼市）：交易、赌命换宝

- WHEN 玩家和某 NPC 对话 THEN 只有该 NPC 的工具能被调用，不会串到别的 NPC
- WHEN 玩家问药老要任务 THEN 药老拒绝并指路去找掌门（角色不混淆）
- WHEN 玩家问夜枭查功法 THEN 夜枭拒绝并指路去找药老

## R4 — NPC 有记忆，不是每次重开
NPC 记得玩家的名字、境界、已完成的任务、之前答应 / 拒绝过的事。

- WHEN 玩家第二天回来找掌门 THEN 掌门能说出上次任务的完成情况
- WHEN 玩家已拿过某支线奖励 THEN NPC 不会重复发同一奖励
- WHEN 对话超过上下文窗口 THEN 只摘要旧对话、不丢关键事实（名字 / 境界 / 任务状态）

## R5 — 关键抉择必须人工确认（interrupt）
赌命换宝、服食未知丹药、渡口引魂这三类有副作用的操作，执行前必须停下来等玩家点「确认 / 取消」，确认后才能执行；取消后状态不变。

- WHEN 玩家触发赌命换宝 THEN 界面弹出确认卡，显示代价（扣多少生命 / 灵力）和可能收益
- WHEN 玩家点取消 THEN 生命、灵力、物品都不变，剧情回到确认前
- WHEN 玩家点确认后刷新页面 THEN 同一笔交易不重复扣费（幂等：同一 `requestId` 只执行一次）

## R6 — 数值规则写死、可验证
状态：生命 / 灵力 / 精力 / 修为 / 攻击。境界：炼气初期 → 炼气中期 → 筑基。
修为满 500 升中期、满 1500 筑基；生命为 0 则重伤回宗门大殿，修为 -50。

- WHEN 修为达到阈值 THEN 自动升境，界面有明确提示
- WHEN 生命为 0 THEN 不死档，回到大殿、修为 -50、生命回满一半
- WHEN 任意数值计算出错 THEN 不出现负数生命 / 超上限修为（护栏拦截并记日志）

## R7 — RAG 查功法 / 丹方是严格的
药老只按知识库回答：知识库里有的才给，没的就说不知道，不编丹方。

- WHEN 玩家问知识库里有的丹方 THEN 给出名称、材料、效果，并标来源
- WHEN 玩家问知识库里没有的 THEN 回答「藏经阁无此记载」，不编造
- WHEN 玩家问无关问题 THEN 不强行扯回丹方，正常对话

## R8 — 界面是终端式、有万圣节氛围，但不挡操作
暗色 + 鬼火绿配色、打字机效果、地点插画感；但所有操作都能点按钮完成，不强制只打字。

- WHEN 玩家在手机上打开 THEN 按钮够大、输入框不被键盘遮住，能正常玩
- WHEN 打字机动画在播 THEN 玩家能点「跳过」直接看全文
- WHEN 网络慢 THEN 有 loading 状态，不出现空白页

## R9 — 能部署、能给评委跑
部署到 Vercel，公开访问；评委不用注册、不用配 key 就能玩到通关（演示用 key 由服务端提供，key 不进前端代码、不进仓库）。

- WHEN 评委打开线上地址 THEN 3 秒内看到开场，不用登录
- WHEN 模型调用失败 THEN 界面提示「灵力不稳，稍后再试」，并给重试按钮，不白屏

## R10 — Kiro 使用痕迹可查
仓库根目录保留 `/.kiro`，spec、steering、hooks 都在仓库里；提交说明里写清用了 Kiro 的哪些功能。

- WHEN 评委打开仓库 THEN 能在 `/.kiro/specs/youming-mud/` 看到 requirements / design / tasks
- WHEN 评委打开仓库 THEN 能在 `/.kiro/steering/` 看到世界观和开发规范
